Une page Hopla est une liste ordonnée de blocs : liens, titres de section, textes, vidéos, produits… L’API les renvoie dans l’ordre d’affichage, chacun avec son `id`.

<RoutesDe tag="Blocs" />

## Types

<ListeTypes />

Sans `type`, un nouveau bloc est un lien. Le type n’est pas modifiable après la création : pour changer de type, supprimez le bloc et créez-en un nouveau.

## Champs

| Champ | Description |
| --- | --- |
| `titre` | Le libellé du bouton, le titre de section ou le texte d’un paragraphe. 160 caractères, 1 000 pour un texte |
| `url` | L’adresse : `https://…`, `mailto:` ou `tel:`. Sans `https://`, Hopla l’ajoute ; une adresse qu’il ne peut pas lire répond 400 `adresse_invalide` |
| `sousTitre`, `description` | Une ligne sous le titre, puis un texte plus long |
| `icone` | Le nom d’un picto ou d’un réseau : `youtube`, `instagram`, `fusee`… |
| `image` | L’adresse https de la vignette |
| `public` | Visible sur la page (`true` par défaut). `false` le garde, masqué |
| `vedette`, `format` | Mis en avant, en `bouton`, `bandeau` ou `carte` |
| `debut`, `fin` | Les dates ISO 8601 entre lesquelles il s’affiche |
| `compteARebours` | Avant `debut`, un compte à rebours plutôt que rien |
| `prix` | Pour un produit, tel qu’il s’affiche : « 29 € » |
| `montants` | Pour `soutien`, les montants proposés en euros |
| `questions` | Pour `faq`, une liste de `{ question, reponse }` |
| `preuve` | Pour `preuve`, `{ genre, note, nombre, source }` |

La [référence de l’API](/reference#model/bloc) détaille tous les champs, y compris ceux en lecture seule.

## Créer un bloc

`POST /blocs` insère le bloc en haut de la page, ou à l’index `position` (0 : en haut).

```bash
curl -X POST https://app.hopla.page/api/v1/blocs \
  -H "Authorization: Bearer $HOPLA_CLE" \
  -H "Content-Type: application/json" \
  -d '{"type": "titre", "titre": "Mes formations", "position": 3}'
```

## Modifier, masquer, programmer un bloc

`PATCH /blocs/{id}` modifie uniquement les champs envoyés ; les autres sont conservés.

```bash title="Masquer un bloc sans le perdre"
curl -X PATCH https://app.hopla.page/api/v1/blocs/a1b2c3d4e5f6 \
  -H "Authorization: Bearer $HOPLA_CLE" \
  -H "Content-Type: application/json" \
  -d '{"public": false}'
```

```bash title="L’afficher du 1er au 15 décembre, avec un compte à rebours avant"
curl -X PATCH https://app.hopla.page/api/v1/blocs/a1b2c3d4e5f6 \
  -H "Authorization: Bearer $HOPLA_CLE" \
  -H "Content-Type: application/json" \
  -d '{"debut": "2026-12-01T09:00:00+01:00", "fin": "2026-12-15T23:59:00+01:00", "compteARebours": true}'
```

Pour supprimer une date, envoyez une chaîne vide : `{"fin": ""}`.

## Dupliquer un bloc

`POST /blocs/{id}/dupliquer` insère une copie juste sous le bloc, avec un nouvel `id`. Avec `{"masquer": true}`, la copie est masquée, ce qui permet de la préparer avant publication.

```bash
curl -X POST https://app.hopla.page/api/v1/blocs/a1b2c3d4e5f6/dupliquer \
  -H "Authorization: Bearer $HOPLA_CLE" \
  -H "Content-Type: application/json" \
  -d '{"masquer": true}'
```

## Images dans un bloc

`image` (vignette d’un lien, photo d’un produit) et `images` (galerie) attendent le chemin d’une image hébergée par Hopla. Envoyez-la d’abord avec [`POST /medias`](/images), puis utilisez le `chemin` renvoyé dans le bloc.

## Réordonner les blocs

`PUT /ordre` attend les `id` de **tous** les blocs, chacun une seule fois, du haut vers le bas. Si un id est manquant, dupliqué ou n’appartient pas à la page, l’API répond 400 `ordre_incomplet` sans rien modifier.

```bash
curl -X PUT https://app.hopla.page/api/v1/ordre \
  -H "Authorization: Bearer $HOPLA_CLE" \
  -H "Content-Type: application/json" \
  -d '{"ids": ["f6e5d4c3b2a1", "a1b2c3d4e5f6", "0a1b2c3d4e5f"]}'
```

## Supprimer un bloc

`DELETE /blocs/{id}` supprime définitivement le bloc. Pour le masquer temporairement, utilisez `{"public": false}`.

## Restrictions selon l’offre

Chaque bloc est soumis aux mêmes validations que dans le back office. En cas de changement d’offre, aucune donnée n’est supprimée : les fonctionnalités non incluses sont conservées et réactivées au retour sur l’offre.
