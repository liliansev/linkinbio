Pages only display images hosted by Hopla: fast loading, no third-party dependency, no visitor tracking. Uploading is a two-step process: `POST /media` stores the image and returns its `path`, then that path is used in settings or in a block.

## Upload

Supported formats: WebP, JPEG or PNG, 1.5 MB maximum. Two upload methods:

<Tabs items={['Raw bytes', 'JSON']} groupId="upload">

<Tab value="Raw bytes">

The request body contains the binary image, with its MIME type in `Content-Type`.

```bash
curl -X POST https://app.hopla.page/api/v2/media \
  -H "Authorization: Bearer $HOPLA_API_KEY" \
  -H "Content-Type: image/jpeg" \
  --data-binary @portrait.jpg
```

</Tab>

<Tab value="JSON">

The image encoded as a data URL, in the `image` field. This is the format used by the MCP server.

```bash
curl -X POST https://app.hopla.page/api/v2/media \
  -H "Authorization: Bearer $HOPLA_API_KEY" \
  -H "Content-Type: application/json" \
  -d "{\"image\": \"data:image/png;base64,$(base64 -w0 logo.png)\"}"
```

</Tab>

</Tabs>

```json title="201 Created"
{
  "media": {
    "path": "/media/054a3c6991bc.png",
    "url": "https://hopla.page/media/054a3c6991bc.png"
  }
}
```

The format is detected from the file signature (magic bytes), not from its extension: a GIF renamed to `.png` returns 415.

## Usage

| Location | Field |
| --- | --- |
| Profile photo | `PATCH /settings` with `{"profile": {"avatar": "/media/…"}}` |
| Page background (Starter) | `PATCH /settings` with `{"backgroundImage": "/media/…"}` |
| Link thumbnail, product photo | Block `image` |
| Gallery | `images` of a `gallery` block, a list of paths |

```js title="Update the profile photo with Node.js"
import { readFile } from 'node:fs/promises';

const key = process.env.HOPLA_API_KEY;
const api = 'https://app.hopla.page/api/v2';

const upload = await fetch(`${api}/media`, {
  method: 'POST',
  headers: { Authorization: `Bearer ${key}`, 'Content-Type': 'image/jpeg' },
  body: await readFile('portrait.jpg'),
});
const { media } = await upload.json();

await fetch(`${api}/settings`, {
  method: 'PATCH',
  headers: { Authorization: `Bearer ${key}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({ profile: { avatar: media.path } }),
});
```

## Errors

| Status | `code` | Cause |
| --- | --- | --- |
| 400 | `missing_image` | Empty body, or `image` is not a data URL |
| 413 | `image_too_large` | Image over 1.5 MB |
| 413 | `storage_quota_exceeded` | Image storage quota exceeded: delete images in the admin panel |
| 415 | `unsupported_image_format` | Format other than WebP, JPEG or PNG |
| 403 | `read_only_key` | The key is read-only |
